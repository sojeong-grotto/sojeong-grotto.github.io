"어느 길로"에 "언제"를 더해

실행 시점의 주행 허가

예약이 있어도 실제 위치가 계획과 다를 수 있어, 구간마다 출발 직전에 다시 확인합니다. 허가 판단은 상태와 예약표를 바꾸지 않습니다.

allowed요청·구간 예약, 출발 시각, 실제 점유, 예상 도착 시각 검사를 모두 통과
waiting계획된 출발 시각 전. 예약은 그대로 둠
replan예약 누락, 다른 로봇 점유, 시간표 초과. 정지가 확인된 뒤에만 예약 해제
문제 · 해결 · 결과

통로 하나를 두고 마주침

PROBLEM
처음에는 경로 전체를 한 로봇이 독점하도록 예약해, 대기 시간이 길고 마주 오는 통로에서 멈췄습니다.
SOLUTION
구간별 시간 창으로 쪼개 예약하고, 같은 자원에서 시간이 겹칠 때만 충돌로 판단했습니다.
RESULT
병목·교차점에서 로봇이 순서대로 통과합니다.

3대가 서로를 기다림

PROBLEM
로봇들이 서로의 다음 노드를 점유하면 아무도 움직이지 못했습니다.
SOLUTION
대기 관계에서 순환을 찾아 한 대를 빈 측면 노드로 양보시키고, 대피 뒤에도 진행 가능한지 복사본 상태로 먼저 검증했습니다.
RESULT
양보한 로봇은 원래 목적지로 다시 계획해 복귀합니다.

재계획 후 남은 이전 경로

PROBLEM
브랜치 병합 후 재계획에 실패하면 이전 경로가 화면과 상태에 남았습니다.
SOLUTION
초기화 누락 지점을 찾아, 실패하면 기존 route를 비우거나 직전 상태를 보존하도록 분기했습니다.
RESULT
목적지 변경이 실패해도 상태가 엇갈리지 않습니다.

표시 안정화 1

미세 진동에 화면이 떨리지 않게

가속도 원시값을 그대로 좌표로 쓰면 주행 중 작은 진동에도 캐릭터가 흔들렸습니다. 중앙 부근에 데드존을 두고, 기울기가 커질수록 빠르게 움직이는 3제곱 이징 곡선으로 바꿔 작은 흔들림은 무시하고 의도한 기울기만 반영했습니다.

표시 안정화 2

바뀐 부분만 다시 그리기

매 주기 화면 전체를 지우고 다시 그리면 깜빡임이 보이고 SPI 전송량이 늘었습니다. 캐릭터의 이전 위치와 겹치지 않는 영역만 배경색으로 지우고 새 위치를 그리는 부분 갱신 방식으로 바꿔 깜빡임과 불필요한 전송을 줄였습니다.

트러블슈팅

LCD ID 값이 예상과 다르게 읽힘

증상
RDDID(0x04) 명령으로 컨트롤러 ID를 읽으면 기대값(0x93, 0x41)과 달랐습니다.
원인
MISO 배선이 연결되지 않아 플로팅 상태의 핀 값이 우연히 읽혔습니다.
해결
FillScreen 색 채우기로 초기화 성공을 별도로 눈으로 확인하고 배선을 점검했습니다.
배운 점
레지스터 읽기는 배선 상태에 좌우되므로 화면 출력 검증을 함께 둡니다.

LCD 모듈의 SD카드 인식 실패

증상
LCD 모듈에 달린 SD카드가 인식되지 않고 읽기에 실패했습니다.
원인
코드 → 전압(3.3V→5V) 순으로 가설을 지운 끝에, DC/RS 핀 자리에 SD_CS가 꽂힌 배선 오류를 찾았습니다.
해결
핀맵을 다시 대조해 배선을 바로잡고 정상 인식을 확인했습니다.
배운 점
가설을 하나씩 지우며 원인 범위를 좁히는 순서를 지킵니다.
