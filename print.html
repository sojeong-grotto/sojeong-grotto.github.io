한 줄 요약

여러 AMR이 공유하는 통로에서의 경로 충돌과 교착에 대응하도록, 로봇별 경로와 통로 사용 시간을 미리 할당하는 교통 관리 기능을 개발했습니다.

결과

주문 → 배차 → 피킹 → 패킹으로 이어지는 물류 흐름 중, FMS 파트에서 다중 AMR의 경로 탐색·통로 사용 시간 예약·교착 해소를 맡았습니다.

설비는 적재를 끝냈는데 HMI 램프가 늦게 켜지거나 이전 메시지가 남았습니다.
CAUSE
PLC 내부 비트와 HMI 표시용 디바이스가 분리되어, 상태가 바뀌는 시점과 화면 값이 갱신되는 시점이 달랐습니다.
SOLUTION
동작 완료 시점에 표시용 디바이스를 함께 갱신하도록 내부 상태 연동 로직을 고쳤습니다.
RESULT
적재·비움 완료 상태가 표시용 디바이스에 반영되어, HMI 램프와 메시지가 설비 상태에 맞게 갱신됩니다.

그룹사 통합 메신저 Qpost
클라이언트 구조·로컬 DB 설계

한 줄 요약

업무 목적과 사용자에 따라 나뉘어 있던 메신저를, 큐텐과 3개 계열사 직원 약 1,500명이 함께 쓰는 하나의 통합 메신저로 재구축했습니다.

결과

기존 로컬 DB를 통합 스키마로 변환하는 마이그레이션과 Microsoft Teams 메시지 연동을 구현했고, 개발 환경에서 재현되지 않는 사용자 환경의 장애를 발생 조건과 실행 흐름을 따라 추적해 해결했습니다.

기능을 단순히 합치지 않고, 사용자 데이터가 어디서 생겨 어떤 경로로 화면에 닿는지부터 분석해 통합 구조를 설계했습니다.

Microsoft Teams 양방향 메시지 연동

Microsoft Graph REST API를 분석해 메시지 수신·전송 구조를 설계했습니다. API를 일정 주기로 조회하고 마지막 업데이트 시각을 로컬 DB에서 관리해 신규 메시지를 구분하는 방식으로, 메시지 중복·누락을 줄이는 동기화 로직을 구현했습니다.

사용자 PC에서만 발생한 비정상 종료 분석·수정
증상
특정 사용자 PC에서 메신저가 비정상 종료됐지만, 개발 환경에서는 재현되지 않았습니다.
분석
발생 당시의 사용 조건을 확인하고, WinDbg로 크래시 덤프의 호출 스택과 실행 흐름을 추적했습니다.
원인
모바일 앱으로 대화하던 상대가 PC 메신저로 넘어와 대화를 이어갈 때, 특정 속성값이 비어 있는 패킷을 처리하는 과정에서 메모리 참조 오류가 발생했습니다.
조치
해당 속성값이 비어 있는 경우를 처리하도록 코드를 수정했습니다.
검증
같은 조건(모바일 → PC 전환)으로 재현해 종료되지 않음을 확인했습니다.
추가 개발·운영 경험
  • SecurityManager · PC의 Hotfix 내역과 설치 프로그램을 서버와 동기화하고, 패치·삭제 알림을 받는 구조 설계
  • 신규 그룹사 전용 메신저와 조직도 추가
  • Teams 조직도 앱(C# Blazor) 기능 추가
  • 출퇴근 체크인·체크아웃, 모바일 수신 전용 채팅창
  • 그룹사 친구 추가·삭제, 스티커, 오픈 채팅
  • 메신저 전체 디자인 리뉴얼
